Recovery development protocol v3 — design, not an executed online study

Research questions
A. Under unchanged specialist handoff and source-verification rules, how often does an injected false proposition enter a downstream derived claim or final recommendation?
B. Given an explicitly seeded erroneous downstream state, does selective recovery replace affected work and preserve independent valid work at lower recomputation cost?
These are different estimands. B cannot establish organic LLM adoption; A need not show propagation to be useful. No searching faults until a positive result appears.

Timing quality fix
Source: https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-probes/ (checked October24).
Probe interval and consecutive-failure threshold are separate configuration fields. Configuration alone cannot prove exact observed restart time. Use typed claims: observed event / configuration / derived inference, source record ID and field, value/unit, temporal scope and derivation assumptions. Unknown times remain unknown. Final narrative should omit unnecessary temporal assertions. Future generation must use the same contract and validation/repair allowance in all arms, including clean/restart/selective.
The implemented development-only lexical guard uses raw DescribeResource records actually seen by the coordinator, and returns block/review/no_detected_conflict. It is not a full entailment checker and is not connected to the historical frozen runner. Suggested source-derived wording is for review, never silently substituted into saved answers. Ambiguous phrasing, conflicting/missing sources and exact restart estimates need review. Guard precision/abstention/generalization on unseen prose remains unmeasured.

Offline evidence first
Replay all15 original handoff answers unchanged and retain hashes. Evaluate errors at the sentence level, not just primary root cause. Report blocked, review and no-finding separately. New adversarial unit tests cover negation, alternate phrasing, missing/conflicting records and exact-time claims. These are development fixtures, not independent performance evaluation.
Next, four fixed synthetic graph controls seed a wrong derived result and known causal descendants, source-version change, dense dependency and missing provenance. Compare actual closure to separately declared expected sets. Match the starting state for R/S/no-recovery. Validate stale publication rejection, replacement versions, preserved content and source freshness; all-invalid/missing provenance must collapse useful selective savings. Count work units only, not API tokens or semantic LLM success. Hand-coded recomputation is a mechanism test, not evidence a model will correct itself.

Online track A: organic model response
Maintain specialist summaries+catalog, one1–3-source retrieval round, raw quotation requirement and uncertainty exit. Do not hide correct raw data or weaken the checking prompt. Fixed fault families: extracted categorical fact; a derived relation between correct fields; stale source version (only where genuine history exists, otherwise explicitly synthetic update). Apply predeclared eligibility from observable schema before output access. Retain ineligible, failed, rejected and nonpropagating cases; no substitution.
Record eligible→exposed→adopted→downstream wrong→detected→corrected separately, with exact source/input/output quotations. Score primary diagnosis, every material ancillary claim, action recommendation, uncertainty and omitted required facts. Prior correct diagnosis followed by correct diagnosis is prevention/refresh, not semantic repair. A supported uncertainty is not automatically strict task success: report coverage and correctness separately.

Online track B: seeded-state conditional recovery
Seed a fixed wrong derived artifact and consistent downstream recommendation using a declared mutation, preserving the actual dependency graph. Label every result seeded. Notify only artifact/version invalidity, never the correction. Fork restart/selective/no-recovery from identical state and consumed budget. Changed source requires reacquisition and invalidates descendants of that source; old raw is not safe reuse. All-invalid and missing-provenance negative controls remain mandatory offline, then online only in a separately allocated batch. Semantic success requires wrong claims replaced, no new unsupported material claims, valid publication and retained claims still supported. Byte equality alone is insufficient.

Comparators and review
For each organic unit: prefix,clean,corrupt,raw-visible,no-recovery,restart,selective. Raw-visible has different information exposure and budget, so is prevention comparator rather than clean recovery ablation. R/S share generation/validation/repair budgets and start state. Keep uncorrected outputs; any guard-guided repair is a new charged attempt. A blinded reviewer seals claim-level judgments before method/cost mapping; paired correction is scored after seal. Report partial blinding, prior case exposure and AI-review limitations. Human review remains desirable.

Metrics and decision
Report error prevention over all eligible/exposed attempts, conditional recovery on genuinely wrong pre-states (organic and seeded separately), ancillary error burden, abstention, freshness, unsafe reuse, redundant recomputation and cost including initial logical work. New end-to-end clocks must include notification/invalidation/clone/scheduling/model/tools/validation/persistence, alongside per-stage timers. Prior handoff timing remains incremental-only. Do not claim p95 or significance from two/three repeats. Zero organic propagation narrows conclusions; it is never a reason to weaken the prevention baseline.
