Experiment plan v0.3 — scope revision 2026-10-21
Authoritative execution priorities; submitted-proposal.txt and prior traces remain historical evidence.

1. Question and causal boundary
Study recovery AFTER a trusted source/version/artifact invalidation notification. Notification identifies invalid material, never the answer. Automatic general error detection is excluded. A human configuration-change clue triggers querying, not an automatic causal rule. Source revisions are controlled constructions over existing snapshots, not real historical incident streams.
Core = safe dependency recovery. Priority extension = multi-group budget scheduling. Second extension = independently gated procedural learning. No production chat integration, live remediation, model training, crash durability, or broad semantic-verifier claim.

2. Claims and counterexamples
C1: with independent reusable work, selective recovery can preserve quality with less recomputation. Counterexample: dense invalidation, expensive validation, or insufficient evidence makes restart/verification preferable.
C2: consumed-input/version tracking blocks invalid descendants and obsolete publications; incomplete capture requires fail-closed fallback. This is tested relative to the captured dependency model, not a proof of real-world causal completeness.
C3: evidence handoff can improve collection but widen the recovery closure. Measure both initial quality and recovery work; do not choose topology from initial token savings alone.
Learning efficacy and scheduling superiority are not prerequisites for these claims.

3. Definitions and outcomes
Separate applied injection, consumed exposure, factual/decision propagation, detected invalidity, refreshed artifact, and corrected answer. A correct root with false supporting facts is not a clean success. Version-only refresh is not wrong-answer repair. Nonmatching/ignored injections stay in the denominator with their state.
Report root/object correctness, native ECR, independent evidence support/source fidelity, output validity, stale-publication rejection separately and as a declared joint success. Independent review reads only actually visible evidence and is not passed back to inference. Freeze semantic sufficiency criteria before formal runs, using only development material; benchmark-required tool paths may differ from semantically sufficient evidence. Preserve both scores and never retroactively replace the native gate.
Uncertain, provider error, timeout, budget rejection, and missing output are unsuccessful scheduled conditions with distinct causes. Show total quality/cost over ALL conditions before secondary cost comparisons on quality-preserving pairs. Include failed/cancelled work and unknown-usage accounting.
Latency = arrival to quality-qualified answer, and invalidation to quality-qualified linked correction. Uncertain-return time is reported separately. Small pilots use per-condition values/ranges, not meaningful population p95 or significance claims.

4. Policy fairness
No-recovery, restart and selective receive the same saved consumed-fault prefix and invalidation notification. Preserve historical ledger and prefix/tool costs; each fork has isolated state and equal resource ceilings.
Consumption-time source-consistency verification is a separate end-to-end baseline with its own prefix; it may prevent corruption. It checks source identity/content/version using available trusted records, not all semantic claims. Charge checks, fresh queries and retries. Do not compare its incremental cost directly with post-fault recovery.
Report initial, incremental recovery and end-to-end calls/tokens/tools separately; shared prefixes count once physically and once per method logically. Track CPU/storage overhead separately from provider latency. Subscription CLI tokens include wrappers and do not imply dollar savings or real RPM/TPM guarantees.

5. Staged matrix, not a full Cartesian product
P0 engineering preflight: existing two collection modes x three invalidation locations x two recovery modes = 12 deterministic conditions. Independently specify expected invalidation sets and cost counters; check state isolation, old-write rejection and settled budgets. Run missing-provenance/publication controls separately. Observable missing provenance now triggers tested full restart, preserving accounting and rejecting old in-flight commits. Controlled tests establish execution safety, not semantic recovery success; budget rejection still counts as unsuccessful. Fake-provider steps are not model quality or token measurements.
P1 semantic feasibility: fixed seen service/1, parallel-one, telemetry-first-one, parallel-two. Existing frozen protocol: at most 10 inference calls, 600000 physical reserved tokens, 240000 per arm, 24 tool attempts, 60000 reservation/call. No retries, no final access, empty memory. Score outputs after inference and audit visible evidence. Fixed order/single case only establishes feasibility. A second run must remain explicitly a development repeat.
P2 core development: use existing seen runtime/service/performance cases to finalize fault contracts and all four baselines. Include unchanged/version-only controls, wrong content, changed-content stale evidence, dense invalidation and incomplete provenance. Do not require every fault to propagate. Confirm baseline validity and measure overhead before freezing formal runs.
P3 formal ceiling: existing final_locked eight incidents remain unopened until protocol and complete-batch budget preflight pass. Predeclare two applicable accidental fault conditions per incident and no-recovery/restart/selective = at most 48 post-fault outcomes, plus eight clean and up to sixteen end-to-end verification outcomes (72 total, one repetition). Eligibility uses tool schema/source availability, not answer labels or prior outcomes. Unmatched faults are recorded rather than replaced. This is a ceiling, NOT a launch authorization or sufficient budget estimate; calibrate and reduce incident count in a new frozen protocol before any held-out inference if needed. Repeats require a separately frozen affordable plan. Eight incidents support limited descriptive evidence; aggregate by incident, never count calls or copied groups as independent samples.
P4 topology sensitivity: parallel versus telemetry-first on a small predeclared development subset under equal diagnosis-round ceilings; parallel-two is a separate round-budget sensitivity, not a pure topology contrast. Combine real clean quality/cost with separately measured recovery branches. Do not add simulated units to real tokens. Final topology choice is fixed before held-out outcomes.

6. Extension gates
Scheduling: only after core baselines and quality scoring pass. Use one fixed recovery/topology and FIFO versus one existing admission/reservation policy, at most 2/4 groups x spaced/burst x two policies = eight initial windows. Include foreground AND recovery completion, queue wait, rejected/unfinished jobs, logical/physical budget, idle capacity and correction delay. Replay and real concurrent calls are separate evidence. Disable learning.
Self-evolve: use learning-only episodes; gate on a separate complete validation batch, provenance-bound review and total generation/validation costs. Existing bundle is inactive; incomplete validation and two service-case savings do not establish efficacy. No requirement to manufacture a successful learning result. Memory revocation controls remain part of core even if learning is omitted.
Integrated demo: one revoked shared-rule version while a fresh group arrives, after standalone controls pass. Demonstrates composition, not a factorial causal study.
