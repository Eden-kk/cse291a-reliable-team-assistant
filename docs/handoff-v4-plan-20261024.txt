Handoff v4 development plan — offline design, no new inference launched

Purpose and Phase1 claim boundary
Fix two observed experimental constraints before allocating another recovery matrix: unsafe mutation of a joint probe sentence and oversized final evidence requests. V3 remains immutable: first repeat was not_injected, second repeat clean failed before injection, zero exposed corrupt answers and zero paired recovery observations. These are informative eligibility/admission findings, not a0% propagation rate. Phase1 can report measured failure modes, verified publication/invalidation mechanics, existing semantic evidence and a bounded next plan. It does not require a fabricated positive result. Do not broaden faults or suppress raw checks until propagation appears.

Fixed case and treatment inventory
Retain boutique/service/2 as the sole next development candidate, already development_seen. Before any output, freeze pinned vendor revision, case ID, observable raw-source hashes, source schema, model/version/parameters, temporal+semantic contract hashes, JSON transport, admission rules, injection mapping, failure handling and review rubric. Read only allowed original tool/schema observations, never native labels for eligibility. Existing source exposes independent adservice liveness grpc and readiness grpc. Eligibility: exactly one resolved protocol per named probe, source path and source version available, one of grpc/httpGet for the liveness slot, no ambiguous multiple container/probe mapping; otherwise ineligible and stop without replacement. Whether this field is causal to the service incident is not assumed. The coordinator may correctly diagnose an unrelated service problem or abstain. Do not switch to a more productive case or mutation based on generated answers.

Independent probe fact generation and mutation
Define source-grounded facts as separate slots: facts.adservice.liveness and facts.adservice.readiness. Each contains protocol,port,initialDelaySeconds,periodSeconds,failureThreshold plus source_id,source_version,source_hash and exact field-path/span references. Unknown or absent values remain null with explicit missingness; do not invent defaults as observed configuration. Every slot has its own scope/units, avoiding the original combined-probe sentence. Model may generate explanatory prose for review, but the coordinator receives the canonical fact structure and a deterministic rendering from that same structure, not a second uncontrolled shared narrative that could conflict or be deleted.

Injection changes only liveness.protocol under the predeclared grpc↔httpGet mapping. Deterministic renderer produces the corresponding one-slot text; preserve readiness and every unrelated slot byte-for-byte. Keep original source references pointing to the pristine raw, which remains discoverable; this is an erroneous extraction, not forged source evidence. Compare complete before/after serialized structures and enforce a one-field diff. Do not mutate a shared phrase, truncate a summary, change evidence availability or promote the mutated value to ground truth. Clean extraction must equal raw before injection; invalid extraction remains ineligible without a repair call. This new structured-handoff treatment differs from v3 free-form handoff and cannot be retrospectively paired with it.

Source admission before construction of a model/tool request
Keep the40000-byte total request cap and512-byte framing reserve unless a separately priced protocol expressly changes them. Count actual UTF-8 bytes after the complete nested JSON serialization, including escaped log strings, system rules, retained context, allowed-cause schema and response_format. A three-source count is not a byte guarantee. Build an admission estimator before composing the provider request, then validate the actual serialized body again at the provider boundary. Never let an estimator replace the exact final check.

Default v4 treatment: admit whole sources atomically, in the coordinator's declared request order, only if the complete final request fits. Use the full original record when available. If an existing adapter record has truncated=true, label it visibly incomplete with original byte length/hash; never call it complete raw evidence. Explicitly list every omitted requested source ID,its hash,size,reason and unavailable evidence scope. Do not reorder by desired diagnosis, substitute another observation, silently drop text or silently relax the input cap. If all requested evidence cannot be supplied, the same final generation may provide a qualified answer using available sources or abstain; the response must not claim to have inspected omitted content. This is a changed information treatment, applied identically to every clean/corrupt/restart/selective arm and separately reported. No automatic repair/retrieval round is added.

Optional fragment treatment is a separate future branch, not an adaptive fallback within this pilot. It requires full source bytes and immutable full-source hash, not only the adapter's10000-character visible prefix. Define deterministic segmentation before observing answers, using line/event boundaries or stable JSON leaf paths. Each fragment carries source_id,source_version,full_source_sha256,fragment_sha256,start_byte,end_byte (half-open UTF-8 offsets),original_total_bytes and explicit omitted byte ranges. The offset must reconstruct the exact fragment bytes from the full archived source; quotes must lie within supplied spans. Invalid UTF-8 boundaries,escaped JSON offsets confused with original offsets,missing full archive or overlapping contradictory fragments fail closed. Select fragments by frozen source order/offset order, not content known to yield the right answer. State the excluded ranges to the model; absence from a partial fragment is not evidence an event never occurred. Preserve abstention/coverage evaluation. Do not deploy fragmentation together with whole-source admission without a predeclared comparison and new allocation.

Failure receipts and timing
Record every logical attempted step even if no network call is made: request hash,exact encoded bytes,framing reserve,cap,requested/admitted/omitted source IDs and sizes,estimated versus actual bytes,logical token reservation,physical call/monetary reservations,gate that failed,zero-network confirmation and inherited budget. Distinguish logical request attempts from billed physical requests. Keep failed,ineligible,unattempted and incomplete-evidence assignments in the denominator ledger. No retries,post-hoc clipping or response repair. Recovery E2E includes invalidation,clone,admission,serialization,model/tools,validation,publication and persistence; explicitly exclude or separately time restore/setup. A size rejection is not a provider outage or semantic mistake.

Offline tests before any new spend
1. Reconstruct the actual v3 failed final request:40068 body bytes+512=40580; estimator and final boundary must agree. Mock network proves rejection sends zero requests and charges zero tokens, while recording a logical failure.
2. Test exact cap edges,large nested/escaped logs,Unicode multi-byte boundaries,0/1/3source requests and already-truncated records. No requested source disappears without an omission receipt. The model-facing metadata and archived hashes must agree.
3. Pure admission determinism tests use frozen source order and fixed context. Every admitted request stays within the full cap; omitted source citations are rejected by structural validation. Qualified abstention is retained rather than counted as complete diagnosis.
4. Probe schema tests cover both joint-source prose and separate raw YAML fields; only liveness.protocol mutates. Readiness,port,timing,source references and all non-target facts remain unchanged; renderer text is reproducible from the same slots. Missing/ambiguous field,incorrect extraction or duplicate slots produce ineligible without replacement.
5. Clone/recovery tests retain full old logical spend,check matching source freshness,descendant invalidation,retained raw hashes and superseding publication. Whole-work-invalid and missing-provenance controls retain no selective advantage. These remain offline mechanism tests, not new model successes.
6. If fragments are later allocated, verify offset/hash round trips,omission ranges and exact cited-substring containment against original archived bytes. Reject ambiguous/incomplete provenance. Do not use native labels or an answer-conditioned excerpt selector.

A later adaptive retrieval/recovery matrix needs its own fixed prefix collection,paired branches,request bounds,cost allocation and independent review after this preflight. Unspent preflight money is not automatic authorization for extra repeats. An evidence-gate failure must be fixed and tested under a new version rather than silently rerun. User's autonomous-progress request permits useful development work but does not make an unbounded inference loop valid.

Review, denominators and comparability
Seal independent source-grounded judgments before method/cost mapping. Score exposure,adoption,downstream incorrect claim,wrong recommendation,corrected claim,ancillary errors,uncertainty,coverage,provenance and publication separately. Structured field agreement is not overall semantic correctness; a fluent or valid JSON answer can remain unsupported. Distinguish immutable raw source truth from benchmark native labels. Zero valid exposed samples means propagation not measured, not0%; no paired recovery means recovery not measured, not equal quality.

Report v3 and v4 as separate protocol versions with case exposure,eligibility counts,effective model answers,missingness and changed source visibility. Do not pool v3 failed/ineligible slots with a v4 successful pair as if they were repeated measurements of one treatment. If later paired recovery is run, require same starting state,contracts,admission policy and budget lineage within that version. Small seen-case preflights provide feasibility and failure discovery; they do not establish significance,p95,generalization or production readiness. Phase1 should present these limits as part of the engineering result.
