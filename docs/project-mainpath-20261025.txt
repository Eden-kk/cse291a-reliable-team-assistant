Project main path — frozen 2026-10-25

Research question
Can dependency-aware selective recovery preserve supported incident responses while reducing recomputation after a trusted partial invalidation?

Evidence used for the main conclusion
1. Formal-v2: 3 independent Cloud-OpsBench cases, 2 repeats each, with every assigned slot retained.
2. Partial invalidation: 4 eligible units. Restart and selective recovery each pass 3/4; the failures differ, so quality equivalence is not established. Selective recovery uses 4 versus 12 calls and 33,260 versus 64,902 incremental tokens (48.8% fewer).
3. All-expiry negative control: both methods use 18 calls across 6 units. Selective recovery therefore degrades to restart-equivalent work when no valid work can be reused.
4. Seeded conditional mechanism check: input-only review supports both final diagnoses and actions; selective recovery retains 8 valid artifacts and uses 15,638 versus 31,142 tokens (49.8% fewer). This is seeded recovery evidence, not organic error prevalence.

Bounded conclusion
Selective recovery is conditionally useful. Under partial invalidation, it matches restart's observed eligible strict-pass count while reducing recomputation. When all prior work expires, it safely loses that advantage and performs restart-equivalent work. The evidence supports cost proportionality and conservative fallback. It does not establish higher diagnosis accuracy, paired quality equivalence, natural fault prevalence, or repair of an organically propagated wrong final diagnosis.
