Scoring is two steps, offline after inference:
1. Independent reviewer reads outputs and observations, not labels; saves JSON
   with reviewer identity, labels_seen=false, input_hashes from
   score_formal_v2.inputs(run), and one rows entry per result directory.
   Each row: supported=yes/no/uncertain; rationale with source references;
   publication_current boolean; fault_adopted boolean. Check ledger validity and
   whether changed numeric content was actually adopted, not just cited.
   python scripts/score_formal_v2.py seal RUN --review REVIEW_JSON
2. Only after the seal validates:
   python scripts/score_formal_v2.py score RUN --vendor PATH
The scorer imports native evaluation/labels only after review and input hashes
match. Strict joint requires diagnosed, JRA=1, ECR=1, supported=yes, current
publication, contract valid and budget valid. Semantic joint omits ECR only.
Uncertain is never success. Assigned-unit statuses remain in the score output;
not-run/failed/not-injected are reported explicitly and never silently dropped.
The evidence-review seal proves immutable reviewed inputs; reviewer independence
is an attestation, not something software can establish by itself.
